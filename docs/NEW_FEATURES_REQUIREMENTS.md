# Требования к инвестиционным модулям Investing Demo

## Контекст и принятые правила

Приложение использует Django, PostgreSQL/SQLite через Django ORM, DRF, Celery/Redis, серверные Django Templates и Plotly. Единственная существующая рыночная сущность — `Share`; текущую цену получает фоновая задача из T-Bank Invest API. Пользовательская модель — стандартная модель Django.

Для первой версии зафиксированы следующие правила:

- Все пользовательские данные доступны только владельцу записи. Чтение каталога и публичной истории цен остаётся доступным без входа; изменение пользовательских данных требует входа.
- Денежные значения и количества хранятся в `DecimalField`. При обработке рыночных данных цена SDK сначала преобразуется из `units`/`nano` в `Decimal`.
- Портфель считает себестоимость методом скользящей средневзвешенной стоимости. Комиссия покупки увеличивает себестоимость позиции; комиссия продажи уменьшает реализованный P&L. Продажа сверх имеющегося количества запрещена.
- Валюта каждой акции должна совпадать с валютой портфеля; автоматической валютной конвертации нет.
- Алерт срабатывает один раз при `price >= target` для условия «выше» или `price <= target` для условия «ниже». Сброс возвращает его в активное состояние.
- История хранит дневные свечи (OHLCV) из T-Bank Invest API. Celery периодически загружает и обновляет дневную историю; повторная загрузка одной свечи обновляет запись, а не создаёт дубликат.
- Бэктестер использует дневные закрытия из локальной БД, не использует будущие данные, торгует одной длинной позицией по одной акции и не моделирует налоги, дивиденды, проскальзывание или валютную конвертацию.

## Функциональные требования

### Персональные списки и алерты

1. Пользователь может создавать, переименовывать и удалять собственные списки наблюдения.
2. Пользователь может добавлять акцию в список и удалять её; одна и та же акция не может дублироваться в одном списке.
3. Пользователь может создавать алерт для акции с направлением «выше»/«ниже» и целевой ценой больше нуля.
4. Фоновая задача проверяет активные алерты после обновления текущей цены акции.
5. Первое пересечение целевого значения атомарно переводит алерт в состояние «сработал» и сохраняет время и цену срабатывания. Повторное уведомление для этого состояния не отправляется.
6. Пользователь может сбросить сработавший алерт; повторное срабатывание после сброса считается новым событием.
7. Сработавшие алерты отображаются как in-app уведомления. Email/SMS/мобильный push в первой версии не входят в объём: соответствующих провайдеров в проекте нет.

### Виртуальные портфели

1. Пользователь может создавать и удалять собственные портфели.
2. Пользователь может записывать BUY/SELL сделки с положительным количеством, ценой и неотрицательной комиссией.
3. Для BUY система увеличивает количество и пересчитывает среднюю себестоимость с учётом комиссии.
4. Для SELL система запрещает продажу большего количества, чем имеется; рассчитывает реализованный P&L по средневзвешенной себестоимости и уменьшает позицию.
5. Портфель показывает позиции, текущую рыночную стоимость, себестоимость оставшихся позиций, нереализованный и суммарный P&L. Поле `return_percent` рассчитывается как суммарный P&L, делённый на сумму всех BUY-сделок с комиссиями; это доля P&L от общего оборота покупок, а не доходность на внесённый капитал. Для оценки позиций используется текущая цена `Share.last_price`; если цены нет, позиция не получает рыночную оценку.
6. Пользователь может просматривать журнал собственных сделок с датой, типом, тикером, количеством, ценой и комиссией.

### История рыночных цен

1. Фоновая задача сохраняет дневные свечи каждой акции в БД и обновляет запись по уникальной паре «акция + время свечи».
2. Пользователь может получить историю по акции за периоды день, неделя, месяц или год.
3. Ответ истории включает свечи и абсолютное/процентное изменение между первой и последней доступной ценой периода; для пустого диапазона возвращается пустой набор без изменения.
4. UI отображает локально сохранённые дневные цены на Plotly-графике и предоставляет выбор периода.
5. Страница подробностей акции использует локальную историю; получение истории из внешнего API остаётся задачей фонового сборщика.

### Симулятор стратегий

1. Пользователь может создать стратегию для одной акции, задав процент падения, окно в днях, целевую прибыль на позицию и начальный капитал.
2. Система запускает симуляцию по дневным закрытиям из локальной истории в выбранном диапазоне дат.
3. Покупка выполняется, если цена закрытия снизилась не менее чем на заданный процент относительно закрытия `Y` календарных дней назад, при отсутствии открытой позиции.
4. При покупке расходуется максимально доступное целое количество акций с учётом комиссии, рассчитываемой как процент от сделки.
5. Продажа выполняется, если цена закрытия достигла заданной доходности относительно средней цены входа. Открытая позиция принудительно закрывается по последней цене диапазона.
6. Каждый прогон сохраняет параметры результата, сделки, конечный капитал, итоговую доходность, максимальную просадку и число прибыльных/убыточных закрытых сделок.
7. Симуляция завершается понятной ошибкой, если в заданном диапазоне нет исторических данных.

## Архитектурные изменения

### Новые сущности

| Сущность | Назначение и ключевые связи |
|---|---|
| `Watchlist` | Список пользователя, владелец — Django User |
| `WatchlistItem` | Связь M2M между `Watchlist` и `Share`; уникальна в пределах списка |
| `PriceAlert` | Условие цены для User и Share; содержит статус/срабатывание |
| `Portfolio` | Пользовательский виртуальный портфель |
| `Transaction` | BUY/SELL, Portfolio, Share, количество, цена, комиссия и реализованный P&L |
| `HistoricalPrice` | OHLCV свеча Share с уникальным временем |
| `TradingStrategy` | Параметры стратегии пользователя для Share |
| `StrategyRun` | Результаты одного запуска стратегии |
| `StrategyTrade` | Сделки и P&L, созданные конкретным прогоном |

### Новые REST endpoints

Все endpoints находятся под `/api/v1/`:

- `watchlists/`, `watchlists/{id}/` — CRUD списков; `share_ids` заменяет набор акций списка.
- `alerts/`, `alerts/{id}/`, `alerts/{id}/reset/` — CRUD алертов и ручной сброс.
- `portfolios/`, `portfolios/{id}/` — CRUD портфелей с рассчитанными позициями/метриками.
- `transactions/` — журнал и создание сделки.
- `history/{share_id}/?period=day|week|month|year` — дневные свечи и изменение за период.
- `strategies/`, `strategies/{id}/`, `strategies/{id}/run/` — CRUD стратегий и запуск симуляции.
- `strategy-runs/` — список сохранённых прогонов текущего пользователя.

### UI

- `/watchlists/` — создание/просмотр списков и алертов.
- `/portfolios/`, `/portfolios/{id}/` — создание портфеля, регистрация BUY/SELL, позиции и журнал.
- `/history/{share_id}/` — график и выбор периода.
- `/strategies/` — создание стратегии, запуск и просмотр метрик/сделок прогонов.

Фоновые задачи Celery: проверка алертов запускается после обновления котировок; отдельная задача регулярно синхронизирует дневную историю. Задачи не отправляют email или внешние уведомления.
